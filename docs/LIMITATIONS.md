# Known Limitations & Honest Scope

This is a **prototype**. We are explicit about what is real and what is a stand-in, so no
scientific or model-accuracy claims are overstated.

## What is genuinely functional
- The **end-to-end privacy pipeline** runs for real: local perception → local PII detection →
  redaction → task-aware minimal context → remote reasoning → local policy → execution.
- The **privacy engine** actually detects and redacts: email, phone (IN), OTP (context-gated),
  credit/debit cards (Luhn-validated), Aadhaar-like, PAN, API keys/tokens, DOB, IPv4, password
  fields, and conservative name/address heuristics.
- The **action-policy engine** genuinely blocks credential/OTP/payment exposure locally.
- The **same shared TypeScript packages** run in both the dashboard and the Chrome MV3 extension.
- **Auth, persistence, audit logging, and the API** are real and typed.
- `assertNoRawPII()` fails closed if a raw value would ever be transmitted.

## What is a deliberate stand-in
- **Reasoning is a `MockProvider`**, not an LLM/VLM. It is deterministic and rule-based. The
  `AIProvider` interface + `RealProvider` stub make replacement a single-file change.
- **PII detection is rule/regex/heuristic**, not an ML/NER model. High precision on the demo
  patterns, but **name and address recognition are intentionally conservative** and will miss
  open-domain cases. A real NER model should be registered as an additional `Detector`.
- **OCR and Vision are interface stubs** with a DOM-text fallback. No real screenshot OCR runs; the
  "screenshot" byte figure in the demo is a representative constant, clearly used only for the
  payload-size comparison.
- **Benchmark data is synthetic**, generated by the seed script and labeled **DEMO / SYNTHETIC**
  everywhere it appears. It demonstrates the intended measurement methodology, not validated results.
- **Database defaults to SQLite** for zero-setup running. The ORM is Postgres-compatible; production
  should use PostgreSQL + Alembic migrations (tables are auto-created on startup here for convenience).
- **JWT logout** is client-side token disposal (no server-side revocation list).
- **Rate limiting** is in-memory (single-process). Use Redis for multi-instance deployments.

## Not attempted (by design)
- No blockchain, no microservices, no fake "live AI" animations backed by hard-coded screenshots.
- No real personal data anywhere — all values are fabricated.

## Threats not yet mitigated
- Adversarial pages that hide PII inside images/canvas would need the OCR/Vision seam implemented.
- Detector evasion (obfuscated PII) is only partially handled; ML detectors would improve recall.
